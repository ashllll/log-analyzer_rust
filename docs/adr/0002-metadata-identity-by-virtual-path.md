# ADR-0002: 元数据按虚拟路径标识，内容按哈希去重

- 状态：已接受（Accepted）
- 日期：2026-07-30
- 背景：后端存储一致性审计

## 背景

CAS 以 SHA-256 标识不可变内容，一个对象可以被多个用户可见路径复用。旧版
SQLite 表却把 `files.sha256_hash` 和 `archives.sha256_hash` 设为唯一，并以
`INSERT OR IGNORE` 写入元数据，导致两个问题：

- 相同内容来自不同路径时，后一个虚拟路径被静默丢弃；
- 同一路径内容更新后，因为哈希不同而产生多条元数据，路径查询可能读到旧记录。

这把“内容身份”和“用户可见路径身份”混在了同一约束中，与 CAS 的职责分离相悖。

## 决策

- CAS 对象继续按 SHA-256 唯一并负责内容去重。
- `files` 和 `archives` 元数据以 `virtual_path` 为唯一身份。
- `sha256_hash` 保留普通索引，允许多个路径引用同一 CAS 对象。
- 重复写入同一虚拟路径时原地更新内容引用和可变元数据，保留稳定的行 ID。
- 旧数据库迁移按虚拟路径保留最新行；归档迁移同时重映射嵌套归档和子文件外键，
  并在提交前执行 `foreign_key_check`。
- 迁移期间暂停 FTS 触发器，完成后重建 FTS，避免外部内容索引与表数据不同步。

## 后果

- 工作区可以完整展示和搜索内容相同但路径不同的文件与归档。
- CAS 仍只保存一份相同字节内容，不增加对象存储占用。
- 按哈希查询只能表示“该内容是否被引用”或返回一个代表性引用；需要枚举可见路径时，
  调用方必须使用路径查询或完整元数据列表。
- schema v4/v5 迁移是启动时一次性事务；迁移失败会回滚，不返回半迁移的
  `MetadataStore`。
